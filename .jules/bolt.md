## 2025-05-15 - Answer fragment reassembly optimization
**Learning:** Reassembling fragmented DNS records in `pkarr::SignedPacket` by repeatedly probing for indices via `resource_records(name)` results in $O(N \cdot M)$ complexity. A single pass over `all_resource_records()` is more efficient ($O(N)$ or $O(M + N \log N)$ if sorting is needed). However, record names returned by the iterator include the full origin zone (e.g., `_answer-<hash>-0.47pjoy...`), so simple prefix matching on the first label alone is insufficient if the target name spans multiple labels or if you expect a bare label.
**Action:** Use `all_resource_records()` for bulk collection. For robust matching, either compare the full `to_string()` of the name or iterate through labels. Always include a fast-path zero-allocation check (like `starts_with(b"_")` on the first label) to keep the scan efficient.
