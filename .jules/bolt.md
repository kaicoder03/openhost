## 2026-07-20 - O(N) single-pass bucket-sort fragment reassembly optimization
**Learning:** Reassembling fragmented answer packets in pkarr was previously implemented via multiple nested probes of `collect_single_txt`. For N fragments, this resulted in O(N^2) complexity, scanning the resource records repeatedly. In addition, absolute resource record names in simple-dns include the zone origin (the publisher's public key) at the end, so prefix comparisons must account for suffix splits. By replacing nested probes with a single pass over `packet.all_resource_records()` and bucket-sorting the matching TXT values by their parsed numeric suffix into an array, complexity is reduced to O(N).
**Action:** Always prefer a single pass over `all_resource_records()` and filter/sort in-memory for name lookups inside a DNS packet instead of calling repetitive lookup helpers.
