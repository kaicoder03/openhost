## 2026-07-20 - O(N) single-pass bucket-sort fragment reassembly optimization
**Learning:** Reassembling fragmented packet values by doing multiple linear scans for consecutive fragment indices on the Pkarr/simple-dns packet (via `packet.resource_records(name)`) incurs an $O(N^2)$ traversal overhead. Since the packet contains all resource records in a contiguous structure, performing a single pass over `packet.all_resource_records()` and bucket-sorting them into a stack-allocated `[Option<String>; 256]` by parsing the `-<idx>` suffix completely eliminates linear scans, reducing complexity to $O(N)$.
**Action:** When reassembling multi-resource or fragmented records under a common prefix from standard DNS/Pkarr packets, always do a single pass over all resource records in the packet to bucket-sort or categorize them instead of performing multiple key-based query walks.
