## 2026-07-28 - Strict Compliance with RFC 7230 §3.2.4 to Prevent HTTP Request Smuggling
**Vulnerability:** The HTTP request-head parser in the local forwarder was lenient about whitespace surrounding header names, because it was trimming the header name slice using `.trim()` before calling `HeaderName::from_bytes`. This allowed headers containing whitespace between the name and colon (e.g., `Host : value`) or leading whitespace (e.g., ` Host: value`) to be successfully parsed.
**Learning:** This lenience violates RFC 7230 §3.2.4, which explicitly mandates that "A server MUST reject any received request message that contains whitespace between a header field-name and the colon with a 400 (Bad Request) response." Differences in whitespace handling between frontends and upstreams can lead to HTTP Request Smuggling, cache-poisoning, and auth bypass.
**Prevention:** Always explicitly check for and reject any request where the raw header name slice starts or ends with space or tab characters. For header values, ensure that optional whitespace (OWS) is securely trimmed at both ends of the value using `.trim_matches([' ', '\t'])` instead of lenient trimming.
