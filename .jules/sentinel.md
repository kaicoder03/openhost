## 2025-05-14 - RFC 7230 §3.2.4 Compliance in HTTP Request Head Parser
**Vulnerability:** The HTTP request head parser in `crates/openhost-daemon/src/forward.rs` was incorrectly trimming whitespace from header field names and failing to trim trailing whitespace from header values. RFC 7230 §3.2.4 explicitly prohibits whitespace between the field name and the colon (e.g., `Host : example`), and specifies that header values should have leading/trailing OWS trimmed.
**Learning:** Ambiguities in HTTP parsing can lead to Request Smuggling or other bypasses. The parser was using `.trim()` on the name part, which effectively masked invalid whitespace before the colon. It also used `trim_start_matches` which ignored trailing whitespace.
**Prevention:** Strictly adhere to RFC 7230 §3.2.4 by ensuring that header names are not trimmed before validation (e.g., passing them raw to `HeaderName::from_bytes`) and that both leading and trailing whitespace are trimmed from values using `trim_matches([' ', '\t'])`.
