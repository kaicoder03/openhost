## 2026-07-28 - Preventing Unix File-Creation Permission Race Conditions
**Vulnerability:** Under Unix-like operating systems, creating sensitive files (such as Ed25519 seed files, DTLS certificates, or peer allowlist configurations) using default creation options and then changing permissions to `0o600` via `set_permissions` introduces a TOCTOU (Time of Check to Time of Use) race condition. An unprivileged local process could open the file for reading during the short window of time before its permissions are tightened.
**Learning:** This issue exists because default file-creation calls use the process's current `umask` (which typically yields permissions like `0o666` or `0o644`). Setting permission bits only *after* file creation leaves a brief vulnerable window.
**Prevention:** Always configure atomic, strict file-creation masks using platform-specific APIs. For Rust filesystem APIs (both `std::fs` and `tokio::fs`), use `OpenOptions` with the `.mode(0o600)` method via the `OpenOptionsExt` trait at the moment the file is created, closing the race window completely.
