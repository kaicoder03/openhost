## 2026-07-25 - [File Permission Creation Race Condition Prevention]
**Vulnerability:** Mitigating file creation permission race conditions on Unix. When creating highly sensitive files (e.g., Ed25519 identity seeds, DTLS certs, pairing allowlists), calling `fs::write` or `File::create` followed by `fs::set_permissions` creates a brief timing window where the file is created with default permissive umask bits (making it readable by other local users) before the permissions are restricted to `0o600`.
**Learning:** This timing window exists because standard file creation doesn't atomic-set permissions. On multi-user systems, local adversaries could continuously monitor directories and read the sensitive data immediately upon creation before `chmod` / `set_permissions` runs.
**Prevention:** Always use `OpenOptions` (either `std::fs::OpenOptions` or `tokio::fs::OpenOptions`) with `OpenOptionsExt::mode(0o600)` on Unix at creation time to ensure the file is created with strict permissions atomically from the very first instruction.
