## 2025-05-14 - [HTTP Header Parsing Strictness and SSRF Defense]
**Vulnerability:** The HTTP/1.1 request head parser in `openhost-daemon` was overly permissive, allowing whitespace between header names and the colon (e.g., "Host : example"). Additionally, several common proxy/CDN provenance headers were not being stripped before forwarding requests to local upstreams.
**Learning:** RFC 7230 §3.2.4 explicitly forbids whitespace before the colon to prevent request smuggling attacks. Generic provenance headers like `true-client-ip` and `cf-connecting-ip` are as critical to strip as the standard `x-forwarded-for` when protecting a local home server from SSRF or IP-spoofing based authentication on the upstream.
**Prevention:** Avoid using `.trim()` on raw protocol components that have strict whitespace requirements in the specification. Maintain an exhaustive allowlist/denylist of security-sensitive headers that must be sanitized before crossing a trust boundary (e.g., from an external WebRTC client to a local loopback service).
